# evateam-notifier

Телеграм-бот-напоминалка задач из таск-трекера [EvaTeam](https://docs.evateam.ru): утренний план дня и предупреждения о просрочках.

Бот напоминает сотрудникам об их задачах из EvaTeam.

## Что делает (MVP)

1. **Онбординг** — сотрудник отправляет `/start`, бот находит его в EvaTeam по полю
   «Telegram» в карточке и сохраняет привязку. Ввода email нет (см. «Доступ» ниже).
2. **Утренний дайджест** — каждое утро бот присылает «план дня»: задачи в работе и ожидающие.
3. **Напоминание о просрочке** — отдельно уведомляет, когда у задачи истёк срок (`deadline`).
4. **Итоги дня (16:00)** — напоминает закрыть выполненное и подвинуть сроки, если планы
   изменились. Показывает задачи в работе и ждущие подтверждения, помечая 🔴 сорванный
   крайний срок и 🟡 отставание от плана. Если закрывать нечего — сообщение не приходит.

## Сводка по проектам (`/summary`)

Управленческий срез для руководителя: активные эпики, сгруппированные по проектам,
с задачами в работе и ждущими подтверждения — исполнитель и плановый срок по каждой.

Команда `/summary` присылает в чат короткую сводку «по исключениям» (что отстаёт, что под
угрозой, блокеры) и прикладывает два файла:

- **HTML-одностраничник** — KPI, дорожная карта по эпикам, таблицы по проектам.
  Самодостаточный: открывается двойным кликом, печатается в PDF (Ctrl+P, A4 landscape).
- **CSV** — в структуре Google Sheets Timeline: импортировать → *Вставка → Таймлайн*.

### Два срока

Отчёт различает жёсткий и мягкий дедлайн — это разные вещи:

| Срок | Поле в EvaTeam | Смысл |
|---|---|---|
| **Крайний срок** | «Крайний срок» (`deadline`) | жёсткий, обязательство |
| **Плановая дата окончания** | «Плановая дата окончания» | мягкий, план |

**Дорожная карта строится по плановым (мягким) датам.** Крайний срок показан на диаграмме
отдельной красной засечкой ▼ и отдельной колонкой в таблицах.

Светофор считается автоматически, **жёсткий срок строже мягкого**:
🔴 сорван крайний срок · 🟡 отстаём от плановой даты либо любой срок в пределах
`SUMMARY_RISK_DAYS` · 🟢 оба срока впереди · ⚪ сроки не заданы.

**Порядок эпиков** задаёте вы, а не светофор: сначала по полю «Приоритет», затем по
пользовательскому полю «Порядок выполнения» (1, 2, 3 — для эпиков с одинаковым
приоритетом). Так во всех трёх местах: дорожная карта, «Требуют решения», таблицы внутри
проектов. Карточки проектов по-прежнему сортируются по светофору. Значок приоритета
показывается рядом с названием эпика, только если приоритет отличается от «Обычного».

Статус эпика и проекта — «худший ребёнок»: сорванный срок задачи красит эпик, даже если у
самого эпика даты нет. Если планового окончания нет, а начало есть — полоса рисуется
открытой («→ ?»). Пропуски (нет срока, нет исполнителя, эпик без задач) показываются
отдельным блоком — отчёт вскрывает дыры в планировании, а не прячет их.

Какие эпики попадают в отчёт, задаёт `SUMMARY_EPIC_STATUS_CODES` (коды `CmfStatus.code`).
Посмотреть текущие статусы эпиков: `python -m evateam_bot.evateam.smoke --epics`.

## Доступ

Права выдаются **в EvaTeam**, а не в конфиге бота — дублировать списки не нужно.

- **Кто может пользоваться ботом.** В карточке сотрудника заполняется поле «Telegram»:
  `https://t.me/username` либо `https://t.me/<числовой id>` (EvaTeam сама дописывает схему).
  При `/start` бот сверяет отправителя с этим полем. Нет записи — нет доступа.
  Сотрудник может привязаться **только к себе**: раньше ввод чужого email открывал
  чужие задачи.
- **Кому доступна `/summary`.** Только участникам группы EvaTeam из `EVATEAM_ADMIN_GROUP`
  (по умолчанию `Admins`) — сводка по всему портфелю управленческая. Проверяется
  при каждом вызове, поэтому исключение из группы действует сразу.

Посмотреть, кто сейчас в группе: `python -m evateam_bot.evateam.smoke --person <email>`.

## Запуск в Docker

```bash
cp .env.example .env          # заполнить токены
docker compose up -d --build
docker compose logs -f
```

**Сертификаты (`certs/`).** Сервер EvaTeam отдаёт только свой сертификат, без
промежуточного (`GlobalSign RSA OV SSL CA 2018`). Windows докачивает недостающее звено
по AIA и потому работает; OpenSSL в Linux — нет, и контейнер падает с
`unable to verify the first certificate`. Промежуточный нужно положить в `certs/`
в формате Base-64 `.crt` — образ ставит его в доверенные.

Экспорт из Windows: `certmgr.msc` → «Промежуточные центры сертификации» → «Сертификаты»
→ найти `GlobalSign RSA OV SSL CA 2018` → правой кнопкой «Экспорт» → Base-64 (.CER)
→ переименовать в `.crt` и положить в `certs/`. Сами сертификаты не коммитятся.

База и отчёты живут в томе `./data`. Разовые задания — тем же образом:

```bash
docker compose run --rm bot python -m evateam_bot.scheduler.jobs --run summary --no-send
```

## Архитектура

Логика отделена от мессенджера через **транспортный фасад** — сейчас Telegram, в будущем MAX
добавляется новым адаптером без изменения ядра.

```
evateam_bot/
  core/         доменная логика (без I/O): модели, дайджест, дедлайны, форматирование
  evateam/      JSON-RPC клиент EvaTeam (сервисный токен) + запросы задач/людей
  transports/   абстракция BotTransport + адаптеры (telegram/, потом max/)
  storage/      SQLite (SQLAlchemy): привязки пользователей, дедуп напоминаний
  scheduler/    APScheduler: утренний дайджест и проверка дедлайнов
  service.py    оркестрация: связывает transport + evateam + storage + core
  app.py        сборка зависимостей
  main.py       точка входа
```

Подробнее — см. [CLAUDE.md](CLAUDE.md).

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows; на *nix: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env         # заполнить токены и URL
python -m evateam_bot.main
```

### Ручной запуск заданий (для проверки)

```bash
python -m evateam_bot.scheduler.jobs --run digest
python -m evateam_bot.scheduler.jobs --run deadlines
python -m evateam_bot.scheduler.jobs --run evening
```

Сводка: `--no-send` только собирает файлы и печатает пути (удобно для отладки вёрстки),
`--chat <id>` отправляет в конкретный чат, без флагов — всем привязанным.

```bash
python -m evateam_bot.scheduler.jobs --run summary --no-send
```

### Проверка подключения к EvaTeam

```bash
python -m evateam_bot.evateam.smoke --person user@example.ru
python -m evateam_bot.evateam.smoke --epics
```
